## 2. 测试数据库隔离

测试专用数据库名为 `a_share_risk_agent_test`。`tests/conftest.py` 在应用导入前设置 `DATABASE_NAME`，因此测试导入的 SQLAlchemy engine 使用测试数据库。

`test_tests_use_test_database` 查询 PostgreSQL 的 `current_database()`，确保测试连接确实落在测试库。

`clean_test_database` 是自动 fixture：每个测试开始前建表并清空三张表，测试结束后再次清空，同时重置自增序号。清理顺序按外键关系执行，并使用 `CASCADE`。

> 不要把测试库设置放进 `test_config.py`。该文件中的数据库配置测试需要独立导入 `Settings` 和 `engine`；公共测试初始化应放在 `conftest.py`。

## 3. 新增自选股接口

### 请求

```http
POST /api/v1/watchlists/{watchlist_id}/stocks
Content-Type: application/json
```

```json
{
  "symbol": "600519.SH",
  "name": "贵州茅台"
}
```

### 行为

- 新股票代码会保存股票资料，并创建自选组关联，成功返回 `201`。
- 同一只股票可以加入多个自选组，股票主记录通过代码复用。
- 股票名称使用数据库中已有的记录，避免相同代码出现名称不一致。
- 自选组不存在返回 `404`。
- 同一股票重复加入同一自选组返回 `409`。
- 代码或名称为空、全为空格或缺失时返回 `422`。

### 分层

- API 层在 `app/main.py` 校验请求并把业务异常转换成 HTTP 响应。
- Repository 层在 `app/watchlists/repository.py` 查找自选组、复用或创建股票记录并添加关联。
- PostgreSQL 的唯一约束作为最后一道保护，阻止相同组合重复写入。

## 4. 从自选组移除股票

```http
DELETE /api/v1/watchlists/{watchlist_id}/stocks/{symbol}
```

- 成功移除关联返回 `204`，响应无正文。
- 自选组不存在或该组没有这只股票时返回 `404`，并给出对应原因。
- `watchlist_items` 中的一行表示“某只股票属于某个自选组”的关系。
- 删除时只删除 `watchlist_items` 中目标自选组与目标股票对应的那一行；不删除整个 `watchlists` 自选组，也不删除 `stocks` 股票主记录，因为其他自选组可能仍引用这只股票。

## 5. 今天遇到的问题

### 测试数据互相影响

移除单个测试中的手动清理后，列表测试读到了前一个测试创建的自选组。自动 fixture 在每个测试前后清理数据库后，测试之间恢复独立。

### 代码和名称只检查了长度

`min_length=1` 会拒绝空字符串，但不会拒绝纯空格。使用 Pydantic `StringConstraints(strip_whitespace=True, min_length=1)` 后，空白会先被去除，再执行最小长度校验。

### VS Code 显示测试失败

接口尚未实现时，新增股票测试得到 `404` 是预期的 TDD 红灯；实现路由和仓储逻辑后，相关测试转为通过。
