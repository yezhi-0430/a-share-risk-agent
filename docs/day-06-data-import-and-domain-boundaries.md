# 第 6 天：日线数据导入与领域边界

## 1. 今天的学习目标

- 明确自选股管理和行情数据导入是两个不同的业务边界。
- 先用测试定义“导入一条日线数据”的行为，再实现最小功能。
- 学会区分外部数据格式、领域模型和数据库模型。
- 不在今天引入真实交易、量化策略或自动下单。

## 2. 今天的范围

今天只做日线数据的最小导入能力，服务于后续的风险监控：

- 接收股票代码、交易日期、开盘价、最高价、最低价、收盘价和成交量。
- 校验必填字段和基本数值约束。
- 同一股票同一交易日不能重复写入。
- 保留股票主记录与日线记录之间的外键关系。

暂不做：真实行情供应商接入、分钟级数据、量化买卖策略和实盘交易。

## 3. 第一个任务：先写测试

先在测试中描述一个成功场景和一个重复导入场景。运行测试时，成功场景应先失败，因为接口和数据表还没有实现；这就是今天的 TDD 红灯阶段。

完成测试后，再决定日线数据模型字段和 API 路径，不直接复制供应商的数据格式。

## 4. 今天已完成

- 新增 `DailyPrice` 数据模型，保存股票、交易日、开高低收和成交量。
- 使用 `stock_id + trade_date` 唯一约束，防止同一股票同一天重复导入。
- 增加股票外键，禁止为不存在的股票写入日线数据。
- 新增 `POST /api/v1/stocks/{symbol}/daily-prices` 接口。
- 正常导入返回 `201`，股票不存在返回 `404`，重复导入返回 `409`。
- 使用 `Decimal` 保存价格，使用整数保存成交量。
- 使用 Pydantic 校验日期、价格类型和非负成交量，非法输入返回 `422`。

## 5. TDD 过程

1. 先写 `daily_prices` 字段测试，观察 `KeyError` 红灯。
2. 实现模型、外键和组合唯一约束，使模型测试通过。
3. 先添加 API 路由骨架，确认未知路由的 `404` 红灯。
4. 增加股票存在性查询和日线保存逻辑。
5. 用数据库唯一约束发现重复导入，再将 `IntegrityError` 转换为 `409`。
6. 增加负成交量测试，再用 `Field(ge=0)` 实现 `422` 校验。

## 6. 当前验证结果

- 全部自动测试通过。
- Ruff 检查通过。
- 测试继续使用专用数据库 `a_share_risk_agent_test`。

## 7. Day 6 复盘

### 我的复盘

- `stock_id` 外键用于保持日线数据和股票主记录的关联，避免日线记录指向不存在的股票。
- 不同股票可以有同一个交易日，所以唯一约束必须是 `stock_id + trade_date`；它表达同一只股票同一天只能有一条日线数据。
- `201` 表示日线创建成功。
- `404` 表示股票资源不存在。
- `409` 表示同一股票同一交易日的数据已经存在，重复导入产生状态冲突。
- `422` 表示请求数据校验失败，例如成交量为负数或字段格式不正确。
- 价格使用 `Decimal`，因为金融价格需要避免 `float` 的二进制精度误差。

Day 6 已完成复盘并通过验收。
