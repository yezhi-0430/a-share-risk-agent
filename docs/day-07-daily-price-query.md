# 第 7 天：日线查询与风险监控数据读取

## 1. 今天的学习目标

- 为指定股票提供历史日线查询接口。
- 按交易日倒序返回数据，让最新行情排在前面。
- 区分股票不存在和股票暂时没有日线数据。
- 为后续风险监控和异常检测准备稳定的数据读取接口。

## 2. 今天完成的功能

新增接口：

```http
GET /api/v1/stocks/{symbol}/daily-prices
```

- 股票存在且有日线时，返回 `200` 和日线列表。
- 结果按 `trade_date.desc()` 排序，最新交易日在最前面。
- 股票不存在返回 `404`。
- 股票存在但没有日线时返回 `200` 和空列表 `[]`。
- 价格序列化为字符串，避免 JSON 浮点精度问题。

## 3. 数据关系

- `stocks` 保存股票主资料，表示“股票是谁”。
- `daily_prices` 保存股票某一天的行情，表示“这只股票当天发生了什么”。
- 查询时通过 `DailyPrice.stock_id == Stock.id` 只读取指定股票的数据。

## 4. TDD 过程

1. 先写查询已有日线并按日期排序的测试。
2. 观察没有 GET 路由时返回 `405 Method Not Allowed`。
3. 实现 GET 查询接口，使排序测试通过。
4. 增加未知股票测试，确认返回 `404`。
5. 增加“股票存在但无日线”测试，确认返回 `200 []`。
6. 运行全套测试和 Ruff 检查，均通过。

## 5. Day 7 复盘

- `404` 表示股票不存在；`200 []` 表示股票存在，但当前没有日线数据。
- 查询按日期倒序，是为了让最新交易日排在第一条，风险监控可以优先处理最近行情。
