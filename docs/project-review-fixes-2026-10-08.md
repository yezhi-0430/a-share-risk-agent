# 项目审查修复记录（2026-10-08）

用户授权修复整项目审查列出的七项问题。本次未增加 Day 11 的自动循环，也未请求真实模型。

| 审查问题 | 修复结果 |
| --- | --- |
| HTTP 日线 JSON 数字先转 float 导致精度丢失 | 日线 POST 使用专用请求解析器直接生成 Decimal；`12345678901234.5678` 可精确入库和查询。 |
| 非正数、非有限值、超位数价格未提前拒绝 | 四个价格限制为有限正数，匹配数据库 Numeric(18,4)；超过 14 位整数或 4 位小数返回 422。 |
| 开高低收之间关系不合法仍可入库 | 校验最低价不超过最高价，开盘价与收盘价均位于二者之间。 |
| 小写股票代码新增成功后无法查询或移除 | API 和 Repository 统一去空白、转大写；已有代码由升级命令规范化。 |
| 并发创建股票或添加自选关联返回 500 | 使用数据库保存点恢复唯一约束竞争：不同组共享同一股票均返回 201，同组重复返回 409。 |
| 默认假模型风险摘要返回 502 | 返回合法离线摘要，评级 unknown，事实、推断和来源为空，未知信息明确说明未分析。 |
| 合法大成交量超过数据库 INTEGER 范围 | ORM 与已有 PostgreSQL 列改为 BIGINT；输入限制在非负有符号 64 位范围，超出返回 422。 |

## 验证

原有测试 221 个，本次增加 26 个回归案例。首次运行新增案例观察到精度、入库、并发、默认假模型和缺少升级实现等失败，再实现修复。

额外边界检查发现 `1e9999` 虽已被价格模型拒绝，但 FastAPI 序列化校验错误时仍会转换成超大整数并返回 500。补充测试复现后，价格路由在错误响应中使用 Decimal 的字符串表示，极大和极小科学计数法均返回 422。

最终全套测试为 **247 passed，2 warnings**。两条警告来自既有 Starlette/httpx 与 AnyIO 依赖弃用提示。Ruff 检查、修改文件格式检查和 diff 空白检查通过。

并发回归使用独立 PostgreSQL 测试数据库，通过同步两个请求的首次查无结果来确定性复现竞争。升级回归先创建旧 INTEGER 列及关联记录，再运行两次升级，验证 BIGINT、代码规范化、数据保留与幂等；另验证代码归一化冲突会回滚，保留原记录。

## 数据库升级

```powershell
.\.venv\Scripts\python.exe -X utf8 -m app.schema_upgrade
```

升级使用一个事务，并在冲突检查与代码更新期间锁定股票表，防止并发写入绕过冲突检查。缺少的表会创建；已是 BIGINT 的列不会重复修改。若发现规范化后相同的股票代码，命令抛出明确错误并回滚；不自动合并股票或行情。

已对本地配置的开发数据库执行相同升级入口，并逐字段比对升级前后的记录。该库当时四张业务表均为零记录，日线表尚未创建；升级后四张表齐备，成交量类型为 BIGINT。旧库含数据的保留场景由上述独立测试数据库回归覆盖。

已有历史行情的数值不会被自动改写或删除。新增校验作用于之后的日线导入。Day 10 补充复盘仍从第 1 题继续。
